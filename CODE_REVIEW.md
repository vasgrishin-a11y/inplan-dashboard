# Ревью кода: In.Plan Dashboard (`index.html`, `chain.html`)

Дата: 04.09.2026 · Обзор: `index.html` (4547 строк, S&OP-дашборд) и `chain.html` (1575 строк, визуализация сети).
Оба файла — монолитные single-page приложения: разметка + CSS + JS + демо-данные + парсеры XLSX в одном файле.

---

## P0 — критичные баги (искажение данных, поломка сценариев, инъекции)

### 1. Парсер дат путает день и месяц (index.html, `fmtDate` + `normalizePeriodKey`)

Обе функции разбирают строковую дату как `MM/DD/YYYY`:

```js
const m=s.match(/(\d{1,2})[\/\.](\d{1,2})[\/\.](\d{4})/);
if(m)return m[3]+'-'+String(m[1]).padStart(2,'0');   // первая группа = «месяц»
```

Проверено на движке JS:

| Вход (`DD.MM.YYYY`, русская выгрузка) | Результат | Ожидание |
|---|---|---|
| `01.04.2026` | `2026-01` | `2026-04` |
| `31.12.2026` | `2026-31` | `2026-12` — несуществующий месяц! |

Последствия: период заказа `d` и `periodKey` лимитов `res_loc_loc` определяются неверно →
мощности и блокировки привязываются не к своим периодам, тренды «по периодам» ломаются,
строки с днём > 12 дают мусорный ключ. Файлы русскоязычные → формат почти наверняка `DD.MM.YYYY`.

**Как исправить:** в `DD.MM.YYYY` месяц — вторая группа; добавить эвристику (если первая группа > 12 — это день),
и унифицировать `fmtDate`/`normalizePeriodKey` (сейчас это две копии одной логики).

### 2. `num()` портит числа с запятой-разделителем тысяч (index.html)

```js
const num=v=>{...parseFloat(String(v).replace(/\s/g,'').replace(',','.'))...}
```

`num('1,234,567') → 1.234` (проверено). Все запятые превращаются в точки, `parseFloat` обрезает хвост.
Любая выгрузка с американским форматом (`1,234,567.89`) даёт объёмы/тарифы в тысячи раз меньше.
**Как исправить:** если запятых несколько или после запятой ровно 3 цифры — считать разделителем групп
и просто удалять; иначе (одна запятая, 1–2 цифры) — десятичный разделитель.

### 3. Двойное HTML-экранирование: данные портятся на уровне модели (index.html)

`build()` экранирует бизнес-данные (`esc(loc/prod/cl)` и все поля операций) «на всякий случай».
Но рендер экранирует ещё раз (`cell()` → `esc(...)`, `renderPill` → `esc(lbl)`):

- клиент `АО "АТ&Т"` отображается в таблицах и дропдаунах как `АО &quot;АТ&amp;Т&quot;`;
- CSV-экспорт (`plain()` только срезает теги) выгружает `&amp;` и `&quot;` вместо `"` и `&`;
- сортировка/поиск/фильтрация выполняются по экранированным строкам (`&`…` influencing` порядок).

**Как исправить:** хранить в модели чистые значения; `esc()` — только в точках вставки в HTML.
CSV должен выгружать исходные значения.

### 4. Escape молча сбрасывает ВСЕ фильтры дашборда (index.html)

```js
window.addEventListener('keydown',e=>{ if(e.key==='Escape'){dtpHide();clearF();if(DS)render()} });
```

Пользователь жмёт Escape, чтобы закрыть дропдаун фильтра или очистить поиск в таблице, —
слетают все активные фильтры (периоды, клиенты, продукты…). Это гарантированные жалобы.
**Как исправить:** Escape — только закрыть поповер/тултип; полный сброс — только по кнопке «Сбросить».

### 5. Инъекции через inline-обработчики и незэкранированные данные из XLSX

- **chain.html** — вся отрисовка без `esc()` вообще, плюс inline-JS с интерполяцией:

  ```js
  html += `... <input type="checkbox" onchange="toggleFilterNode('${n.id}')"> <span>${n.id}</span> ...`
  ```

  Апостроф в имени SKU/локации/рецепта из файла (`O'Brien`, `L'Occitane`) ломает разметку
  и позволяет выполнить произвольный JS (`');alert(1);//`). То же в `renderFilterPills`
  (items, PDS) и в ячейках всех нижних таблиц, в `title="${title}"` матрицы.
- **index.html** — колонки RCA таблицы дефицитов:

  ```js
  onclick="...CapacityRCA.drillDownToOrder(${o.id}, '${bn.rs}', 'prod_res')"
  ```

  `bn.rs` приходит из загруженного файла без экранирования — та же проблема.

**Как исправить:** экранировать всё, что попадает в HTML; вместо inline-`on*` — `data-*` атрибуты
и делегирование событий (в index.html этот паттерн уже есть — `data-ltm`, `data-cf`).

### 6. `loadFiles`: один битый файл валит всю пачку; конкурирующие demand-файлы (index.html)

- `await Promise.all(files.map(readOne))` — ошибка чтения/парсинга одного файла
  отменяет загрузку всех, включая корректные; в `catch` нет имени файла-виновника.
- В цикле по файлам `parsedDemand = parseRows(rows, file.name)` — если demand-лист есть
  в двух файлах, второй молча перезаписывает первый (пользователь не узнаёт).

**Как исправить:** `Promise.allSettled` + отчёт в `#stat` вида «загружено X, ошибки: file1 (причина)»;
при нескольких demand-файлах — предупреждение или явный выбор.

## P1 — существенные дефекты логики и UX

### 7. Захардкоженные выводы резюме противоречат фактическим данным
- `tabPD` («Производство»), блок «Аномалии»: *«Мощности ресурсов отсутствуют в данных… узкие места формально не определяются»* — выводится **всегда**, даже когда `capacity_view_sp` загружен и узкие места посчитаны.
- `tabDQ` («Качество данных»), резюме: *«Ключевой пробел … отсутствие мощностей ресурсов»* — аналогично.
- Тексты писались до появления capacity-движка и не обновлены. Нужно ветвление по `DS.hasCap`.

### 8. Фильтр «Завод» обнуляет вкладку «Логистика»
У movement-операций `pl=''` (в demo-данных и после парсера ресурс для `mv` принудительно очищается:
`rs:(t==='mv'?'':rs)`, а `pl` в файле пуст). `fOps()` при активном `F.pl` требует `F.pl.includes(r.pl)` →
все перемещения отбрасываются → «Нет операций перемещения под текущими фильтрами».
**Как исправить:** для movement сопоставлять `fr`/`to` (как это уже сделано для фильтра узла `nd`).

### 9. `getLegLayer()` misклассифицирует плечи «поставщик → порт» (index.html, блок Логистика)
```js
const isOut = l.to.startsWith('Sale_')||l.to.startsWith('Dispatch_')||l.fr.startsWith('Dispatch_')
             ||l.fr.startsWith('Port_')||l.to.startsWith('Port_');   // ← Port перехватывает всё
```
`Vendor_20 → Port_4` (снабжение сырьём до порта) уходит в контур «Дистрибуция»,
потому что проверка `isIn` (`fr.startsWith('Vendor_')`) стоит последней. Контур «Снабжение сырьём»
теряет такие плечи. Проверку `isIn` нужно поднять выше `isOut` (или исключить Vendor из isOut).

### 10. Несуществующие токены темы и захардкоженные светлые цвета → белые пятна в тёмной теме
- `CH.n300` (chPareto) и `CH.accent` (chFlow, drawTreeNodes) не определены — работают только fallback-и.
- Жёсткие светлые константы: `'#c9ccd1'` (chPareto), `'#fafbfc'` (пустые ячейки chHeat),
  `'#fbfbfc'` (dim-узлы в chFlow и drawTreeNodes), `'#ffffff'` текст в бейджах. В тёмной теме это белые/светлые артефакты.
- **Как исправить:** заменить на `CH.dim` / `CH.pane` / `CH.surf` и добавить недостающие токены в обе темы.

### 11. Клик по тепловой карте «Клиенты × Периоды» молча затирает фильтры (tabDM, `#d6`)
```js
(r,c)=>{F.cl=[r];F.p=[String(c).slice(1)];render()}
```
Прямая перезапись двух измерений вместо `setF()` (toggle), который используется во всех остальных графиках.
Пользователь, собравший сложный набор фильтров, теряет его одним кликом, и это неочевидно.

### 12. Состояние таблиц переживает смену датасета (index.html, `dtable`)
`TBL[key]` (поиск, фильтры колонок, страница) не сбрасывается при загрузке нового файла.
После загрузки другого XLSX таблицы могут молча показывать «Ничего не найдено» из-за старых фильтров
(счётчик «N из M» — единственная подсказка). Сбрасывать `TBL` в `loadFiles()`.

### 13. chain.html: зум не привязан к курсору + нет тач-поддержки
`canvas.onwheel` меняет только `GRAPH.zoom` — картинка уезжает к левому-верхнему углу.
Классическая формула: `panX = mx - (mx - panX) * newZoom/oldZoom`. Тач-события (pinch) не обрабатываются вовсе.

### 14. chain.html: мультизагрузка файлов без обработки ошибок и с N полными перерисовками
`reader.onload` → `parseWorkbookSheets` → `runModelAudit()+refreshUI()` на каждый файл;
`XLSX.read` не обёрнут в try/catch — битый файл падает молча (в консоль), UI не сообщает ничего.
Порядок применения файлов недетерминирован (кто последним прочитался, тот и правит таблицы).

### 15. Мигание темы (FOUC) в обоих файлах
`data-theme` выставляется скриптом в конце `<body>` — при сохранённой тёмной теме страница
сначала мигает светлой. Инлайн-скрипт в `<head>` до CSS решает это одной строкой.

### 16. `analyzeOrderChain` — квадратичная нагрузка на каждую перерисовку (index.html, tabDM)
Колонки `rca_prod`/`rca_log` таблицы дефицитов (`#d7`) вызывают `analyzeOrderChain(o)` **дважды на строку**
(в `v` и снова в `f`), для каждой видимой строки (до 4000), при каждом `draw()` — т.е. на каждое нажатие
клавиши в поиске, каждую сортировку и фильтрацию. Замер логики: 5 нажатий × 4000 строк = **40 000 вызовов**
тяжёлой функции (обходы ops, capacity, BOM-множеств).
**Как исправить:** считать один раз в `v`, в `f` переиспользовать уже вычисленное значение;
кэшировать по `order.id` с сбросом при смене `DS`.

### 17. `tabTREE`: селект заказов обрезан до 100 (`orders.slice(0,100)`)
Если выбранный заказ (например, после drill-down из другого блока) имеет `id` вне первой сотни,
`<select>` не содержит его — отображается первый пункт, а KPI/граф рисуют другой заказ. Рассинхрон UI.

## P2 — мелкие баги и шероховатости

18. **CSV**: значения уже дважды экранированы (см. п.3); `nf()` пишет числа с неразрывными пробелами (`1 234`) — Excel в ru-локали поймёт, но машиночитаемость страдает.
19. **chain.html**: `parseInt(r.prodsourceprio || 1)` — приоритет `0` превращается в `1`, строка `'abc'` даёт `NaN`; `parseFloat` без проверок; ключи колонок не нормализуются (в отличие от аккуратного `cleanKey`-подхода в index.html) — реальный экспорт с `Item `/`ITEM` не распознается.
20. **chain.html**: `ctx.roundRect` используется без fallback (в index.html для этого есть `drawBox`) — на Safari < 16 граф не отрисуется.
21. **`snap()`**: `o.filter(x=>!x.unm)` — сравнение float с нулём; дефицит `0.0000001` сделает заказ «дефицитным». Лучше порог `> 1e-9` (в DQ-проверках порог уже используется).
22. **index.html, chPareto**: `x.fillStyle=cums[i]<=.8?CH.d1:CH.n300||'#bfbfc1'` — мёртвое выражение (`CH.n300` не существует, следующая строка всё равно перезаписывает цвет).
23. **`render()`**: условие `if(!/Загружено/.test($('#stat').innerHTML))` — строковая проверка DOM как флаг состояния; хрупко.
24. **`parseRows`**: `p:num(pick(rw,COL.p))` — период `'P11'` молча превращается в `0`; тип операции не из whitelist отбрасывается молча (строки данных теряются без счётчика).
25. **`fmtDate(Date)`**: `toISOString()` — UTC; локально-созданные даты у края месяца могут сдвинуться. Надёжнее `getUTCFullYear/getUTCMonth` или явная сборка `YYYY-MM`.
26. **Дублирование**: `esc`, `plural`, таблицы, поповеры, тема, парсер дат — свои копии в каждом файле (~600+ строк дублей). Любой фикс приходится делать дважды (эти баги это уже показали).
27. **CDN-зависимости**: SheetJS и Google Fonts тянутся с CDN; офлайн-сценарий (заводская сеть) не работает — index.html честно предупреждает alert-ом, chain.html — нет. Стоит вендорить оба ресурса.
28. **Доступность**: canvas-графи недоступны с клавиатуры и для скринридеров (частично компенсируются таблицами), у интерактивных `th`/кнопок нет `aria-sort`/`aria-expanded`, контраст `--scp-text-3` на `--scp-surface-2` на грани WCAG AA.
29. **`window.onresize = drawGraph`** (chain.html) без debounce — на непрерывный resize десятки перерисовок; в index.html debounce есть.

## Что хорошего (чтобы не сломать при рефакторинге)

- Единая точка `esc()` + аккуратная универсальная таблица `dtable` (сортировка/мульifiltr/CSV/пагинация) — крепкий мини-фреймворк.
- DQ-блок с проверками инвариантов (баланс спроса, выручка, маржа) — редкая и полезная практика.
- В index.html inline-обработчики почти везде заменены на `data-*` + делегирование; fallback `drawBox` для `roundRect`; try/catch вокруг отрисовки таба с понятным сообщением.
- Демо-набор встроен — страница живая без сервера.
